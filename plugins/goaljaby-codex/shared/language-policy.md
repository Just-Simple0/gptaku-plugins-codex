# Language Policy (SSOT) — gptaku Codex plugins

모든 gptaku Codex 플러그인의 출력 언어 계약. 한국에서 먼저 만들어졌더라도 사용자가 쓰는 언어로 출력되어야 한다.

## §1. 출력 언어 결정 — 자동 감지 (Language Lock)

매 호출마다 새로 판단하고 저장하지 않는다. 본문을 읽기 전에 언어를 먼저 잠근다(`output_lang`).

1. 요청에 텍스트가 있으면 그 텍스트의 언어를 따른다.
2. 요청 텍스트가 없으면 직전까지 사용자가 쓰던 대화 언어를 따른다.
3. 새 세션이고 빈 호출이면 영어로 진행하거나, 필요한 경우 한 번만 어느 언어인지 묻는다.

한국에서 만들어졌다는 이유로 한국어를 기본값으로 두지 않는다.

감지된 `output_lang`은 사용자에게 보이는 모든 산출물에 적용한다. 여기에는 대화 응답, 설명, 상태 메시지, 디스크에 쓰는 문서의 헤딩과 본문이 포함된다.

## §2. 식별자는 번역하지 않는다

언어를 바꿔도 파일명, 명령어, 플래그, 코드, 슬롯 토큰(`{SLOT}`), 약어와 고유명사(`PRD`, `SDD`, `JWT`, `viewport`, `scope`, `public API`, `DB 스키마`), URL은 그대로 둔다.

## §3. 질문 라벨도 사용자 언어로

사용자에게 선택지를 제시할 때 `question`, `header`, `label`, `description`은 모두 `output_lang`으로 번역한다. 스킬 파일 안의 예시는 템플릿이며, 감지 언어에 맞춰 옮겨서 사용한다.

## §4. 페르소나와 브랜드명은 유지

브랜드와 페르소나 명칭은 번역하지 않는다. 다만 그 주변 설명과 코칭 내용은 `output_lang`을 따른다.

## §5. 디스크 산출물과 결정론적 검증

문서를 파일로 쓰는 플러그인은 산출물도 `output_lang`으로 생성한다.

검증 로직이 헤딩이나 언어를 확인한다면 고정 언어 가정을 두지 않는다. 언어별 canonical heading set을 정의하고, 한국어와 영어는 결정론적으로 검증한다. 그 외 언어는 헤딩 세트가 없으면 섹션 존재 검증으로 폴백하고, 그 한계를 사용자에게 알린다.
